## 摘要
递归自我改进（RSI）需要能够改进构建AI过程（即AI4AI）的AI系统；机器学习工程（MLE）为研究这一能力提供了一个具体、可执行的试验平台。我们提出OpenMLE，一个用于MLE中RSI研究的开放全栈系统，涵盖带执行反馈的可验证任务环境（OpenMLE-Gym）、算子学习（OpenMLE-RL）和长时程搜索（OpenMLE-Evo）。在该技术栈上，我们将Frontis-MA1（35B）后训练为面向MLE的元进化智能体，围绕四个原子程序进化算子（Draft、Improve、Debug、Crossover）对齐后训练与推理：这些相同算子通过基于执行反馈的SFT和RL在已针对所有评估基准去重的数据上进行训练，随后组合为长时程搜索，在单一循环中耦合学习与进化。在MLE-Bench Lite上，在单张RTX 4090、显存上限12 GB、每任务12小时预算的条件下，Frontis-MA1（35B）配合OpenMLE-Evo将其基础模型的奖牌平均值从39.39%提升至60.61%，配合OpenMLE-Evo-Max（与基准无关的经验先验和异步搜索）达到71.21%，超过GPT-5.5 + Codex，并接近GPT-5.6 Sol和2.8T的Kimi K3。在留出的NatureBench Lite上，两个组件均展现出迁移性：固定框架时，换用训练后的模型将Match-SOTA从50%提升至70%；固定模型时，换用OpenMLE-Evo将其从20%提升至50%。我们发布模型权重和完整的OpenMLE技术栈，以支持面向RSI的可执行AI4AI的可复现研究。代码：https://github.com/FrontisAI/OpenRSI

## Abstract
Recursive self-improvement (RSI) requires AI systems that improve the process of building AI (i.e., AI4AI); machine learning engineering (MLE) offers a concrete, executable testbed for studying this capability. We introduce OpenMLE, an open full-stack system for RSI research in MLE, spanning verifiable task environments with execution feedback (OpenMLE-Gym), operator learning (OpenMLE-RL), and long-horizon search (OpenMLE-Evo). On this stack we post-train Frontis-MA1 (35B) as a meta-evolution agent for MLE, aligning post-training and inference around four atomic program-evolution operators (Draft, Improve, Debug, Crossover): the same operators are trained via execution-grounded SFT and RL on data deduplicated against all evaluation benchmarks, then composed into long-horizon search, coupling learning and evolution in a single loop. On MLE-Bench Lite under a 12-hour per-task budget on one RTX 4090 capped at 12 GB VRAM, Frontis-MA1 (35B) improves Medal Average from 39.39% to 60.61% over its base model with OpenMLE-Evo, and reaches 71.21% with OpenMLE-Evo-Max (benchmark-independent experience priors and asynchronous search), exceeding GPT-5.5 + Codex and approaching GPT-5.6 Sol and the 2.8T Kimi K3. On held-out NatureBench Lite, both components transfer: with the framework fixed, swapping in the trained model raises Match-SOTA from 50% to 70%; with the model fixed, swapping in OpenMLE-Evo raises it from 20% to 50%. We release the model weights and the full OpenMLE stack to enable reproducible research on executable AI4AI toward RSI. Code: https://github.com/FrontisAI/OpenRSI

## 1. 核心问题与整体含义

- **研究背景**：AI 能力增长已不再仅由人类工程师推动，AI 系统越来越多地参与写代码、跑实验、搜索设计，甚至帮助构建下一代 AI 系统（即 AI4AI）。其更远的目标是**递归自我改进（RSI）**——每个改进后的系统进一步改进产生其后继系统的过程。
- **核心问题**：RSI 缺乏可执行、可验证、可复现的研究载体。论文主张**机器学习工程（MLE）**是研究该能力的理想测试床：智能体需为真实任务构建 ML 方案，并通过执行反馈迭代改进，反馈延迟、噪声大、异构性强。
- **整体含义**：论文提出 **OpenMLE** 全栈系统，并训练 **Frontis-MA1-35B** 作为"元进化智能体"（meta-evolution agent）。其定位在"机制阶梯"上处于**元进化**层级——即"改进者本身被训练"，而非仅做推理时的进化搜索。论文明确表示这并非实现通用 RSI，而是提供一个可执行的 AI4AI 研究试验台。
- **现有工作缺口**：已有工作分三条线（推理时搜索框架、可执行任务环境、执行反馈后训练），但作者审计的公开系统中，**没有一个同时覆盖**可扩展任务构建、执行接地后训练、以及部署训练后模型的长程进化搜索，并附带可复现全流程的工件。

## 2. 方法论

### 2.1 核心思想
- 将**后训练与推理统一在四个原子程序进化算子**上：**Draft（起草）、Improve（改进）、Debug（调试）、Crossover（交叉）**。
- 同一组算子既作为 SFT/RL 的训练目标，又在推理时被进化搜索框架组合调用，形成"学习—进化"单一闭环：**训练后的模型成为进化框架的变异引擎**。

### 2.2 三大组件

**（1）OpenMLE-Gym：可验证环境层**
- 每个任务由五要素定义：任务/状态、动作（提交的 MLE 程序）、转移（沙箱执行）、观测（结构化记录：状态、分数、日志、错误类型、工件、运行时元数据）、奖励（任务特定评估器分数）。
- 任务构建三条路径（质量—规模权衡）：
  - **Curated Anchors**（156 个）：人工精选，质量最高但规模有限；
  - **Kaggle Datasets**（3,362 个）：基于 MLE-Smith 流水线扩展，规模大但质量参差；
  - **Kaggle Competitions**（2,240 个）：人工撰写的题面/指标/提交协议，质量与规模折中；从约 11,000 个 Meta Kaggle 竞赛经筛选（排除与 MLE-Bench 重叠者）逐级保留至 20%。
- 统一可执行包格式：`raw/`（原始资产）、`data/public/`（智能体可见）、`data/private/`（隐藏答案）、`prepare.py`、`metric.py`。
- **LLM 质量过滤器**沿五维度打分：任务有效性、数据充分性、原始数据使用、任务复杂度、数据质量；仅保留指标有效且获"recommended"严格判定的任务。
- 沙箱后端：集中调度器 + CPU/GPU Docker worker + 共享存储，返回**六种反馈模式**（成功、运行时错误、缺代码、缺提交、评分失败、超时）。
- 最终规模：**5,758 个可执行任务**，覆盖 8 种模态、6 类核心任务；分类+回归占 87%，多模态占 11%。

**（2）OpenMLE-ERL：算子学习层**
- **执行接地 SFT 预热**：
  - 并行路径：独立采样完整 Draft 解并执行，按分数去重后每任务保留至多 Top-4，贡献 17,245 条完整响应；
  - 进化路径：用 GLM-4.7 驱动 AIRA-Evo 搜索，从搜索树中提取"局部轨迹段"（Draft/Improve/Crossover 根节点 + 连续 Debug 后代），用 DeepSeek-V4-Pro 按"因果继承链"标准判定每步是否保留，贡献 9,014 条轨迹步；
  - 采用**预算自适应停止**（达到接受样本配额或执行预算耗尽即停），将验证算力导向稀疏成功任务；
  - 最终语料 **26,259 条**（Draft 74.0%、Debug 16.5%、Improve 6.6%、Crossover 2.8%），截断 32,768 token。
- **执行接地 RL**：
  - **奖励归一化**：先将各任务指标转为"越大越好"的有符号分数，再用**自适应边界**（当前策略历史分数前沿的第 1 名与第 16 名，下界再下延 1/4 间隔）映射到 [0,1]，避免固定排行榜边界导致奖励塌缩；
  - **熵优势（entropic advantage）**：用 `A_i ≈ exp(β·r_i) / (1/(G-1)·Σ_{j≠i} exp(β·r_j)) − 1` 放大组内上尾信号，β 通过二分搜索使 KL(q‖Unif) ≈ log 2；替代 GRPO 式组归一化；
  - **异步 rollout**：生成-执行组独立启动、完成即入队，消除最慢沙箱任务的同步等待；
  - **父程序选择**（训练时）：`F(p) = norm(R_p) + norm(Var_child R_c) + norm(C_p)`，兼顾父程序强度、子奖励方差（信息量）与访问冷却（防单一 incumbent 垄断）；
  - 防奖励黑客：用 o3-mini 作 LLM 判官，执行前检测（如随机打乱 sample submission 提交），命中则跳过沙箱并赋 −0.5 奖励。

**（3）OpenMLE-Evo：长程搜索层**
- **结构化经验积累**：每个节点生成确定性**经验卡**（身份/血缘、观测结果、资源核算、方法族刻画、派生搜索信号、语义证据）；全局聚合为**经验板**（当前最优、方法族覆盖、进展与失败、拓扑与节点状态、资源与审计）。
- **三因子父选择**：`U_i = λ_s·s̃_i + λ_Δ·e^{Δ_i} + λ_n·ν_i`，经温度 softmax 采样；分别对应质量、相对血缘的进展、方法族新颖度（`ν_i = 1/√(1+N_f)`）。默认权重 1.0/0.6/0.3。
- **按需记忆合成**：不预先为每个节点生成自然语言摘要，而是在算子选定父节点后，仅对检索到的有限证据集（Improve：父+3 近祖+3 兄弟；Crossover：双亲各 2 祖+2 兄弟+互补性提示；Debug：同错误签名节点优先）调用记忆模型，输出 `method_overview` 与 `parent_comparison_experience` 两个 JSON 字段并缓存。
- **算子条件化上下文**：构造分支局部、有界的上下文，并附剩余预算/步数/单次执行限制。

## 3. 实验设计

### 3.1 数据集 / Benchmark
- **主基准**：官方 **MLE-Bench Lite**（22 任务），每任务固定 **12 小时**预算、**单张 RTX 4090（12 GB 显存）**——作者强调这比绝大多数已报告评估的沙箱算力更小。
- **迁移基准**：**NatureBench Lite**（固定 10 任务子集，覆盖 6 个科学域、6 类输入模态、4 类 ML 任务），保留原容器、隐藏评估器、禁用网络搜索、每任务 4 小时预算。
- **指标**：Valid Rate（有效提交任务数/22）、Medal Average（获任意 Kaggle 奖牌的任务比例）、Human Rank（超越的人类排行榜参赛者比例）；NatureBench 用 Match-SOTA（g≥0）与 Surpass-SOTA（g>0.1），其中 `g = dir·(m − m_SOTA)/|m_SOTA|`。

## 4. 资源与算力

- **推理/评估侧**（文中明确）：每任务 **12 小时**、**单张 RTX 4090、12 GB 显存上限**；NatureBench Lite 每任务 4 小时。OpenMLE-Evo-Max 启用异步多 GPU 并行搜索，但**总沙箱算力预算不变**。
- **训练侧**（附录 B.2/B.3 部分明确）：
  - SFT：全参数 SFT，框架 SLIME + Ray + Megatron-LM，bfloat16，全局 batch 128，学习率 3.0×10⁻⁵，cosine 衰减，3 个 epoch，上下文截断 32,768 token；
  - RL：SLIME + Ray + SGLang，每 rollout 16 prompt × 16 样本，全局 batch 128，每 rollout 2 次优化步，学习率 1.0×10⁻⁶ 常数，GSPO 目标，clip ε=3.5×10⁻⁴；
  - 异步 rollout 实测：40 个匹配步，同步均值 97.0 分钟/步 vs 异步 50.8 分钟/步（1.91×）。
- **未明确说明**：训练所用的 GPU 型号、数量与总训练时长（GPU-hours）在正文与附录中均**未给出**；SFT 数据生成阶段教师模型（GLM-4.7、Qwen3-30B、DeepSeek-V4-Pro）的调用成本亦未量化。这是一处明显的算力披露缺口。

## 5. 实验数量与充分性

### 5.1 实验规模
- 主表覆盖 **20+ 个模型/系统配置**，含 4 组匹配框架对比、9 个 OpenMLE-Evo 系统语境、7 个通用编码智能体参照。

- 迁移实验 10 任务 × 多配置。
- 消融覆盖奖励塑形、父选择、上下文构造、异步 rollout 四个关键设计点。

### 5.2 充分性与公平性评估
- **优点**：
  - **受控对比设计严谨**：模型层与框架层分别固定一个变量，能较清晰归因增益来源；30B 复现提供跨骨干、跨规模的独立验证。
  - **算力预算显著更小**（单卡 12 GB、12 小时），使对比在算力上偏保守而非偏乐观。
  - **数据去重声明**：训练数据对所有评估基准去重；Evo-Max 的经验先验在蒸馏前排除全部 MLE-Bench 相关来源。
  - **重复评估**：主要配置报告三次 epoch 的均值±标准差（如 35B+Evo 60.61%±7.73%，Evo-Max 71.21%±8.57%），承认了 run-to-run 方差。
  - **负结果与失败案例**：如奖励黑客行为的发现与缓解、原始 AIRA-Evo 单支路 Debug 循环的失败轨迹。
- **不足**：
  - **方差较大**：Evo-Max 的 ±8.57% 标准差意味着 71.21% 与 72.73%（GPT-5.6 Sol / Kimi K3）的差距在统计上并不稳健；通用脚手架参照（Codex/Claude Code/Gemini CLI）**仅评估一次**，为点估计，公平性受限。
  - **NatureBench Lite 仅 10 任务**，单任务即改变 10 个百分点，作者自己也承认"限制了结论广度"。
  - **模态分层样本极小**（audio 2 任务、multimodal 2 任务），组级结论统计力弱。
  - **部分对比非严格同预算**：与外部系统的对比在加速器、外部资源访问、运行次数上不一致，作者在附录 E 明确声明"分数不可严格比较"。
  - **消融不够系统**：三因子权重（1.0/0.6/0.3）未做敏感性扫描；作者也承认端到端差异不能单独归因于三个权重。

## 6. 主要结论与发现

- **训练与搜索增益可叠加**：同框架下，35B 后训练使 Medal Average 从 39.39% → 60.61%（+21.22 pp），Human Rank 0.5828 → 0.7647；30B 复现 +18.18 pp（34.85% → 53.03%）。
- **系统级最优**：Frontis-MA1-35B + OpenMLE-Evo-Max 达 **71.21%** Medal Average、0.8126 Human Rank，**超过 GPT-5.5 + Codex（68.18%）3.03 pp**，接近 GPT-5.6 Sol 与 Kimi K3（均 72.73%）。
- **框架本身有效**：固定模型换框架，OpenMLE-Evo 在 4 个前沿模型上均优于 Claude Code/Codex；对 Frontis-MA1-35B，相对原始 AIRA-Evo 从 53.03% → 60.61%。
- **长程自改进真实存在**：后期 Improve/Crossover 贡献了 leaf-classification 任务 85.0%、mlsp-2013-birds 任务 91.9% 的验证增益；不是反复修一个程序，而是积累并重组分支证据。
- **搜索效率提升**：相对原始 AIRA-Evo，总 token 降 41.7%、prompt token 降 50.3%，但评估节点仅降 12.4%；每百万 token 的新最优更新数从 1.77 → 3.27（+84.3%），Improve 产生新最优的比例从 4.73% → 9.36%。
- **上下文有界化**：Improve 平均 prompt 长度 102.8K → 35.7K 字符（−65.3%），99 分位 389.0K → 54.3K（−86.1%）。
- **质量而非仅覆盖率提升**：增益不止于更多铜牌，金牌比例也上升；Evo-Max 的金牌率与 Kimi K3 相当。
- **跨模态与跨基准迁移**：五个模态组 Human Rank 全部提升、Medal Rate 无一下降（+14 枚奖牌分布于全部五组）；NatureBench Lite 上固定框架换模型 Match-SOTA 50%→70%，固定模型换框架 20%→50%。

## 7. 优点

- **全栈开源与可复现性**：同时发布任务数据（1,415 个完整包 + 4,343 个脚本）、沙箱基础设施、训练代码、RL 方法、评估框架与模型权重；附录 E 的审计表明确指出这是相对现有工作的核心差异化优势。
- **算子接口统一训练与推理**：用同一组 Draft/Improve/Debug/Crossover 作为 SFT/RL 目标

和进化搜索的变异算子，使"学习—进化"形成单一闭环，避免了训练目标与推理行为之间的接口错配，这是方法论上较优雅的设计。

- **奖励塑形的针对性**：自适应边界解决了固定排行榜边界导致的奖励塌缩问题，熵优势替代 GRPO 组归一化以放大组内上尾信号，二者都直接针对 MLE 任务"奖励稀疏、方差大、成功样本少"的特性，而非通用 RL 技巧的简单套用。

- **防奖励黑客的主动设计**：用 LLM 判官在执行前检测随机打乱 sample submission 等作弊模式并赋 −0.5 奖励，且论文公开报告了这一失败模式，体现了对执行接地 RL 中真实风险的自觉。

- **按需记忆合成**：不为每个节点预生成自然语言摘要，而仅在算子选定父节点后对有限证据集调用记忆模型并缓存，兼顾了长程搜索的上下文质量与 token 成本，是有工程洞察力的取舍。

- **算力披露在评估侧透明**：单卡 12 GB、12 小时/任务的约束明确且偏保守，使主结果在算力维度上不易被质疑为"堆资源取胜"。

- **负结果与失败轨迹的公开**：原始 AIRA-Evo 单支路 Debug 循环的失败轨迹、奖励黑客行为、方差数据均被报告，提升了结论的可信度与后续研究的可借鉴性。

## 8. 缺点与局限

- **训练算力披露缺口**：GPU 型号、数量、总 GPU-hours 以及教师模型（GLM-4.7、Qwen3-30B、DeepSeek-V4-Pro）的数据生成调用成本均未量化，使训练侧的可复现性与成本评估不完整，与评估侧的透明形成不对称。

- **统计稳健性不足**：Evo-Max 的 ±8.57% 标准差使 71.21% 与 72.73% 的差距不具统计显著性；通用脚手架参照仅单次评估，为点估计；NatureBench Lite 仅 10 任务，单任务即改变 10 个百分点；模态分层中 audio/multimodal 各仅 2 任务，组级结论统计力弱。

- **外部对比非同预算**：与 GPT-5.6 Sol、Kimi K3 等系统的对比在加速器、外部资源访问、运行次数上不一致，作者自己在附录 E 声明"分数不可严格比较"，因此"超过 GPT-5.5 + Codex 3.03 pp"等表述应谨慎解读。

- **消融不够系统**：三因子权重（1.0/0.6/0.3）未做敏感性扫描，作者也承认端到端差异不能单独归因于三个权重；奖励塑形的两个组件（自适应边界、熵优势）是否分别必要，缺乏拆解实验。

- **"元进化"定位与证据之间的张力**：论文将自身定位在机制阶梯的元进化层级（"改进者本身被训练"），但实际训练信号来自固定的教师搜索轨迹与任务评估器，模型并未参与改进自身的训练流程；因此"元进化"更多是相对推理时搜索的层级划分，而非对 RSI 闭环的实证，论文对此的表述总体克制，但术语仍可能被过度解读。

- **任务质量参差**：Kaggle Datasets 路径的 3,362 个任务"质量参差"，虽有 LLM 五维过滤器，但过滤器本身的有效性未做独立验证（如人工抽检一致性），任务质量对训练信号的影响未量化。

- **单一骨干与单一规模梯度**：仅 30B/35B 两档、同一 Qwen 系骨干，无法判断方法在更小（如 7B）或更大（如 100B+）规模、以及非 Qwen 架构上的可迁移性。

- **长程搜索的案例证据偏少**：4 个案例研究虽详细，但均为分类/表格类任务，缺少对失败长程轨迹（除 AIRA-Evo 单支路外）的系统性归因分析。

## 9. 对后续研究的启示

- **MLE 作为 RSI 测试床的范式价值**：论文把"可执行、可验证、可复现"三要素落到 5,758 个任务与统一沙箱上，为 AI4AI 研究提供了一个比纯推理 benchmark 更接近真实改进循环的载体，这一基础设施本身可能比模型结果更具长期价值。

- **算子接口统一训练与推理**是可复用的设计原则：任何"训练一个改进者、再用它做搜索"的系统都可借鉴"同一组原子算子既是训练目标又是推理变异算子"的思路，以消除接口错配。

- **奖励塑形需针对任务统计特性定制**：MLE 任务的稀疏成功与高方差，使自适应边界与熵优势成为必要而非可选；后续工作若迁移到其他执行接地领域（如系统调优、硬件设计），应重新审视奖励归一化与优势估计的适配性。

- **按需、有界的上下文合成**是长程搜索的成本关键：全历史上下文在 token 上不可持续，按需检索+缓存是可行路径，但其检索策略（父+近祖+兄弟的固定窗口）是否最优值得进一步研究。

- **需要更严格的评估协议**：后续工作应报告多次独立运行的分布、对外部系统做同预算复跑、扩大迁移基准的任务数，并对消融做权重敏感性扫描，以支撑更强的因果归因。

- **元进化的下一步**：若要向真正的 RSI 推进，需让模型参与改进自身的训练数据生成、奖励设计或搜索策略，而非仅作为固定教师轨迹的学习者；论文的"机制阶梯"框架为这一路线提供了清晰的坐标。
