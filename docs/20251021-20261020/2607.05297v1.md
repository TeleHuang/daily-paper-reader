## 摘要
近期的LLM智能体正在处理日益长程、开放式的任务，而外部技能（提供给智能体的可复用程序性知识）进一步扩展了这一能力。然而，固定的、手工编写的技能很少是最优的，也无法适应智能体所遇到任务的多样性。自我改进的智能体通过从执行轨迹中重写自身的技能文件来解决这一问题，在具有挑战性的基准上取得了显著收益。然而，这种自我演化仍然是非递归的：它只改进任务技能（智能体做什么），而改进过程（如何改进）只编写一次并保持固定。我们提出了MetaSkill-Evolve，一个双时间尺度框架，使智能体技能改进具有递归性：每个分支同时携带一个任务技能$s$和一个分支局部元技能$m=(ψ,σ,α,π,\varepsilon)$，其五个组件分别参数化改进流水线中的Analyzer、Retriever、Allocator、Proposer和Evolver智能体。任务技能在快速循环上演化，而元技能在较慢的循环上、在应用于自身的同一流水线下演化，无需额外的模型或目标。在所有五个流水线智能体共享单一冻结骨干的情况下，MetaSkill-Evolve在三个智能体基准（OfficeQA、SealQA、ALFWorld）上优于无技能、静态技能和单层演化基线，相较于原始骨干，在留出测试准确率上分别提升了+23.54、+16.09和+1.92个百分点。

## Abstract
Recent LLM agents tackle increasingly long-horizon, open-ended tasks, and external skills, reusable procedural knowledge supplied to the agent, further extend this capability. However, a fixed, hand-authored skill is rarely optimal, and cannot adapt to the diversity of tasks an agent encounters. Self-improving agents address this by rewriting their own skill files from execution traces, yielding meaningful gains on challenging benchmarks. Yet such self-evolution remains non-recursive: it improves only the task skill (what the agent does) while the improvement procedure (how it improves) is authored once and held fixed. We introduce MetaSkill-Evolve, a two-timescale framework that makes agentic skill improvement recursive: every branch carries both a task skill $s$ and a branch-local meta-skill $m=(ψ,σ,α,π,\varepsilon)$ whose five components parameterise the Analyzer, Retriever, Allocator, Proposer, and Evolver agents of the improvement pipeline. Task skills evolve on a fast loop while the meta-skill evolves on a slower one under the same pipeline applied to itself, with no additional model or objective. With all five pipeline agents sharing a single frozen backbone, MetaSkill-Evolve outperforms no-skill, static-skill, and single-level evolution baselines on three agentic benchmarks (OfficeQA, SealQA, ALFWorld), improving held-out test accuracy over the raw backbone by +23.54, +16.09, and +1.92 points respectively.

## 1. 核心问题与整体含义

- **背景**：LLM 智能体越来越多地处理长程、开放式任务，外部“技能”（skill，即 Markdown 格式的可复用程序性知识文件）成为扩展其能力的重要手段。但手工编写、固定不变的技能难以适应任务多样性。
- **已有进展**：EvoSkill、GEPA、SkillWeaver 等自改进系统通过“分析—提议—演化”流水线，从执行轨迹中重写技能文件，在困难基准上取得明显收益。
- **核心缺口（非递归性）**：这些系统只改进“任务技能”（智能体做什么），而改进过程本身（如何诊断失败、如何提议编辑、如何分配搜索预算、如何复用跨分支经验、如何落盘）是一次性写定、全程固定的。因此它们只是“自我改进”，而非“递归自我改进”。
- **关键洞察**：技能演化搜索实际受两个量支配——当前技能效用 \(U(s)\) 与元生产率 \(P(m|s)\)（当前改进策略产生更强后代的速率）。只优化前者会忽略“哪条分支的改进策略仍然有效”，导致固定元过程在反复出现同类失败时停滞。
- **研究问题**：能否用同一套智能体流水线，把改进过程本身作为一等对象与任务技能共同演化？

## 2. 方法论

### 核心思想
- 每个分支状态为 \(b=(s,m,h)\)：任务技能 \(s\)、分支局部元技能 \(m=(\psi,\sigma,\alpha,\pi,\varepsilon)\)、迭代历史 \(h\)。
- 元技能五个组件分别参数化五个专职智能体：
  - \(\psi\)：Analyzer，诊断策略，把失败映射为标签 \(\phi\) 与分析 \(a\)；
  - \(\sigma\)：Retriever，共享策略，选取同分支/跨分支灵感；
  - \(\alpha\)：Allocator，分配策略，设定每次的子代预算 \(K\in[1,K_{\max}]\)；
  - \(\pi\)：Proposer，编辑提议策略，生成编辑 \(\delta\)；
  - \(\varepsilon\)：Evolver，编辑执行策略，写盘并校验。
- **关键设计**：每个元技能组件本身也是与任务技能同格式的 Markdown 文件（SKILL.md），因此同一套五智能体流水线可递归地作用于 \(m\) 自身——实现有界的一级递归，无需额外模型或目标函数。

### 双时间尺度
- **快循环（每次迭代）**：从前沿父节点恢复快照 → 在训练批上取最差样本 → Analyzer 诊断 → Retriever 检索灵感 → Allocator 定预算 \(K\) → Proposer 生成 \(K\) 个编辑 → Evolver 落盘校验 → 在验证集评估增益 \(\Delta U_k\)。
- **慢循环（每 \(H\) 次迭代）**：以窗口内经验元生产率 \(\hat P(m|s)=\frac{1}{|H|}\sum_{u\in H}\Delta U_u\) 及标签/诊断/结果构造“元失败轨迹” \(f_m\)，再用同一流水线改写五个元技能文件。三个特殊处理：
  - 约束式 Analyzer：目标为空或指向任务技能时，对五组件轮询回退；
  - 整体重写：每轮同时编辑全部五个文件（Proposer 串行、Evolver 并行），保持组件间一致性；
  - 累积子代：第 \(k+1\) 个子代读取第 \(k\) 个子代写后的文件，形成增量精炼。

### 演化图与前沿选择
- 搜索历史持久化为 SQLite 中的有向无环图 \(G=(V,E)\)，节点存 \((s_v,m_v,U_v,\Delta U_v,\phi_v)\)、分支路径与选择计数；边分“血缘边”与“灵感边”。
- 仅当 \(\Delta U_v>0\) 的子代进入可部署档案；中性/退化子代仍保留在图中供检索灵感。
- 前沿选择分数：\(v^*=\arg\max_{v\in F}[\eta_1 U_v+\eta_2\hat P_v+\eta_3 N_v]\)，其中 \(N_v=1/(1+\text{times\_selected}_v)\)。三项分别对应利用、轨迹质量、访问冷却，且不按血缘过滤——多样性是分数的性质而非结构约束。

## 3. 实验设计

- **基准**：三个互补能力的智能体基准
  - OfficeQA（企业文档端到端接地推理）
  - SealQA（搜索增强推理）
  - ALFWorld（文本具身交互任务成功率）
- **数据划分**：按类别列分层抽样为训练（失败挖掘）、验证（子代评分与最优技能选择）、留出测试（演化循环从不观察）三部分；测试集通过独立的 benchmark-mode 评估。
- **骨干**：单一冻结的 Gemma-4 31B，五个流水线智能体共享，无任何微调，收益全部归因于演化出的技能与元技能。
- **对比方法**：
  - No-Skill（无技能、关闭反思）
  - Static Skill（手工初始技能固定不变）
  - Single-Level Evolution（快循环开启、慢循环冻结，\(K_{\max}=1\)、无跨分支共享、无元技能更新）
  - MetaSkill-Evolve（完整双时间尺度系统）
- **消融**：\(-\psi\)、\(-\sigma\)、\(-\alpha\)、\(-\pi\)、仅去跨分支检索（\(-\sigma_x\)）、冻结慢循环（no meta-updates）；另有元更新horizon \(H\in\{2,4,8\}\) 扫描、跨分支检索强度敏感性、训练/验证划分比例扫描。

## 6. 主要结论与发现

- **主结果**：留出测试准确率相对原始骨干提升 OfficeQA +23.54、SealQA +16.09、ALFWorld +1.92 点；相对 Single-Level 分别 +6.38、+8.05、+1.92 点。
- **单调递进**：两个 QA 基准上 No-Skill → Static → Single-Level → Ours 严格单调，说明“加技能、演化技能、演化演化过程”三个设计各自独立有效。
- **慢循环是饱和场景下的唯一有效成分**：ALFWorld 上静态技能反而退化（−1.93），单层演化仅回到基线，全部 +1.92 点增益来自元技能适应。
- **主导组件随领域而异**：OfficeQA 上分配策略 \(\alpha\) 最关键（−19.7 点），SealQA 与 ALFWorld 上提议策略 \(\pi\) 最关键；跨分支共享在 ALFWorld 上贡献了全部增益。
- **Horizon 越短越好**：\(H=2\) 在所有基准最优，OfficeQA 对元技能陈旧最敏感（\(H=2\to8\) 掉 9.1 点）。
- **饱和基准需要足够大的验证集**：ALFWorld 上扩大验证划分（0.10→0.25）带来 +2.0~+4.3 点，因为小验证集暴露的失败太少，演化循环缺乏信号。

## 7. 优点

- **概念清晰**：把“改进过程”提升为一等可演化对象，用 \(P(m|s)\) 明确区分“当前分数高”与“改进策略仍有效”，是对递归自我改进的一种务实、有界的落地形式。
- **零架构开销**：元技能复用任务技能的 Markdown 表示与同一五智能体流水线，不引入新模型、新目标函数、新框架，工程上优雅且可移植。
- **分支局部策略**：元技能按分支携带而非全局共享，允许不同血缘发展出不同的诊断/编辑风格，跨分支仅通过元层检索传播逃逸策略。
- **前沿分数设计有针对性**：三项分别对应贪心搜索的三种失效模式（追高噪声、停滞高原、预算垄断），且多样性内嵌于分数而非硬约束。
- **实验归因干净**：冻结骨干 + 单调递进 + 精确复现 Single-Level 的消融，使增益归因可信；消融粒度细（区分整体 Retriever 与仅跨分支）。
- **诚实的负结果与边界讨论**：如实报告 ALFWorld 上静态技能退化、划分扫描样本小、绝对数值不可逐格对齐等。

## 8. 不足与局限

- **递归深度有限**：仅实现一级有界递归，流水线的角色与接线（五智能体结构本身）固定不变，作者在 Limitations 中自认。
- **元更新调度固定**：\(H\) 为固定超参，未做自适应调度；且 \(H\) 敏感性在 OfficeQA 上很大（9.1 点），默认值选择的稳健性依赖基准。
- **算力不可复现**：未报告 GPU 型号/数量/时长，演化循环的实际成本（每迭代多次 LLM 调用 × 并发评估）难以评估，限制了可复现性与成本效益判断。
- **统计效力不足**：单次运行、无方差报告；部分结论（SealQA 静态技能、划分扫描）落在噪声内；ALFWorld 近天花板导致结论外推受限。
- **基准覆盖有限**：三个 curated 基准，未涉及开放式、长程、反馈噪声大的真实任务；作者自认迁移性未验证。
- **潜在偏差风险**：训练/验证/测试按类别分层划分，但演化循环以“最差训练样本”为诊断目标，可能对类别分布敏感；跨分支检索过强会引入噪声（作者已观察）。
- **应用限制**：依赖 SQLite 图存储与文件系统快照恢复机制，分支隔离依赖运行时正确恢复快照，工程实现复杂度不低；元技能整体重写可能覆盖快循环已取得的有效编辑（\(H\) 过大时的失效模式）。
