## 摘要
递归自我设计是指由AI辅助修改AI系统构建、评估和改进机制的过程。本文将MetaAI视为一个工作术语，而非成熟范式，用以描述一种由人类播种、AI扩展的开发模式，其中设计空间本身成为修改对象。我们提出了一个操作性证据框架，包含四项标准：可检查的目标系统、元级修改器、反馈导向的选择以及递归延续。随后，我们将公开系统（包括Darwin Goedel Machine（DGM）、STOP、Goedel Agent和ShinkaEvolve）与这些标准进行对照。DGM提供了目前报告的最直接证据：其已发表结果显示，经过80次迭代后，在SWE-bench Verified上从20%提升至50%，在完整Polyglot上从14.2%提升至30.7%，消融实验表明开放式探索和自我改进均有贡献。最后，我们提供了MetaAI-Mini，一个基于HumanEval的可复现协议和代码库。由于本构建中未包含完整的模型运行，MetaAI-Mini作为协议而非实验结果进行报告。

## Abstract
Recursive self-design refers to AI-assisted modification of the mechanisms by which an AI system is built, evaluated, and improved. This paper treats MetaAI not as a mature paradigm, but as a working term for a human-seeded, AI-expanded development pattern in which the design space itself becomes a target of modification. We propose an operational evidence framework with four criteria: inspectable target system, meta-level modifier, feedback-directed selection, and recursive continuation. We then map public systems, including Darwin Goedel Machine (DGM), STOP, Goedel Agent, and ShinkaEvolve, against these criteria. DGM provides the most direct currently reported evidence: its published results show improvement from 20% to 50% on SWE-bench Verified and from 14.2% to 30.7% on full Polyglot after 80 iterations, with ablations suggesting that both open-ended exploration and self-improvement contribute. Finally, we provide MetaAI-Mini, a reproducible HumanEval-based protocol and codebase. Because no completed model run is included in this build, MetaAI-Mini is reported as a protocol rather than as an experimental result.

## 2. 方法论

### 2.1 四项操作性判据（核心贡献）

递归自我设计被定义为同时满足以下四条的迭代过程：

1. **可检查的目标系统**：目标 AI 系统的架构、工具、工作流、提示、记忆或代码级策略可被检查和修改。
2. **元层修改器**：由 AI 驱动的过程提出修改，而非随机扰动或人工补丁。
3. **反馈导向的选择**：候选修改在外部任务/效用函数上评估，反馈影响后代保留。
4. **递归延续**：被保留的后代可作为后续改进轮次的起点。

关键放宽：不要求全神经网络权重自改写；冻结基础模型下的**代码级 agent 脚手架**是合法目标，因为 agent 性能大量取决于工具使用、上下文管理、搜索、验证与工作流设计。

### 2.2 与普通优化的形式化区分

- **边界内优化**（设计空间固定）：
  - \(D_{t+1} = D_t,\quad x_{t+1} = \Omega(x_t; D_t)\)
- **递归自我设计**（改变搜索与行动的系统本身）：
  - \(S_{t+1} = \Psi(S_t, R_t, C_t)\)
  - 其中 \(S_t\) 为当前 agent 设计，\(R_t\) 为经验反馈，\(C_t\) 为约束集（沙箱、benchmark 协议、人类监督）。

### 2.4 DGM 协议流程（论文复述的实例化）

1. 人类 0-to-1：定义种子编码 agent、工具、benchmark、档案规则、沙箱、评估协议。
2. 初始化档案 \(A_0 = \{S_0\}\)。
3. 迭代 \(t = 1,\dots,80\)：从档案采样父代 → 父代检查自身日志 → 提出并实现代码级自我修改 → 在分阶段 benchmark 任务上评估子代 → 若可编译且保留代码编辑功能则保留。
4. AI 1-to-N：保留的后代成为未来父代；报告最佳档案 agent。

## 6. 主要结论与发现

- **有界可行性成立**：DGM 80 轮后 SWE-bench Verified 从 20%→50%（+30 个百分点），完整 Polyglot 从 14.2%→30.7%（+16.5 个百分点），且基础模型权重未变。
- **递归组件确有贡献**：去掉开放式探索降至 23%/14%，去掉自我改进降至 39%/28%，greedy 选择为 39.7%/30%，均低于完整 DGM 的 50%/38%。
- **档案机制关键**：greedy 与无档案变体均不具竞争力，说明保留低分"踏脚石"、维持多谱系对递归自我设计重要。
- **功能保留是前提**：完整 DGM 有 51.3% 生成 agent 保留基本代码编辑能力，消融组仅 32.5%——破坏自身修改能力的系统不满足递归延续判据。
- **改进是结构性的**：细粒度文件查看、字符串替换编辑、补丁验证与重试、上下文窗口管理、多补丁生成与排序、历史感知补丁生成等改变了 agent 的"操作基质"，而非标量调参。
- **实现细节决定成败**：两个同样瞄准"更细粒度编辑"的 SWE-bench 节点分别达到 23.3% 与 40.5%，说明递归自我设计不只是选特征，更是发现能保留功能并提升性能的实现细节。
- **边界明确**：基础模型冻结、benchmark 与保留规则由人编写、DGM 未修改外层开放式探索循环——因此不构成 RSI 或 AGI 证据，更非"智能爆炸"临近的证据。

## 7. 优点

- **概念贡献清晰**：四判据把模糊的"自我改进"拆成可检查的工程条件，并形式化区分边界内优化与递归自我设计（式 1 vs 式 2）。
- **诚实的证据分级**：用 Full/Partial/Limited 定性映射多系统，明确标注"非独立复现、非能力绝对排名"。
- **消融逻辑有说服力**：通过"无自我改进"与"greedy/无档案"两个反事实基线，排除"固定元 agent"与"单纯爬山"两种替代解释。
- **可复现性意识强**：公开 GitHub 代码库、固定数据划分、记录来源校验和、强制区分 `mock` 与 `api` 运行、默认拒绝用 mock 数据绘图。

## 8. 不足与局限

- **实验覆盖窄**：证据几乎全部来自 DGM 一个系统、两个编码 benchmark；未覆盖非编码领域（数学、科学发现、机器人等）。
- **无独立复现**：本文为二次分析，未重跑 DGM，也未提供 MetaAI-Mini 的任何 API-backed 结果，核心可复现性主张尚待验证。
- **统计严谨性不足**：未报告随机种子、方差、置信区间；DGM 结果本身是随机且昂贵的，端点数字的稳定性未知。
- **MetaAI-Mini 设计偏弱**：仅 10 条 HumanEval 任务、单谱系重写循环、默认 5 代、本地非安全沙箱执行生成代码，统计功效与安全性都有限；作者自认其为"课堂复现"用途。
- **映射主观性**：四判据的 Full/Partial/Limited 标签是定性判断，缺乏评分细则与标注者一致性检验。
- **外层循环不可修改**：DGM 未修改开放式探索循环本身，因此"递归"深度受限；作者也承认这是边界。
- **偏差风险**：以编码 agent 为中心可能高估脚手架修改的收益（编码任务天然适合代码级自我编辑）；benchmark 与保留规则由人设计，存在对齐/过拟合风险。
- **应用限制**：自我修改系统可改动工具、评估器、日志、上下文处理与执行路径，安全风险内生于方法本身；论文仅提出治理建议，未做安全实验评估。
- **未来方向（作者提出）**：发布机器可读谱系数据、逐代 diff、评估轨迹与失败修改记录；跨出编码领域；在保障措施下使外层改进循环可修改；将安全作为一等评估结果。
