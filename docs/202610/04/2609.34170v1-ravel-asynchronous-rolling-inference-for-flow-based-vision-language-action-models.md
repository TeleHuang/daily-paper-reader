## 摘要
基于流的视觉-语言-动作（VLA）模型在通用机器人操作中非常有效，但其依赖计算开销高昂的 VLM 编码和多步迭代式动作生成，这带来了显著的延迟瓶颈。由此产生的推理延迟使机器人难以快速响应，尤其是在动态环境中。我们通过 RAVEL（滚动异步 VLA 实现低延迟控制）来解决这一限制；这是一种异步推理框架，可同时应对 VLM 主干网络和动作专家的计算瓶颈。为减少多步动作去噪带来的延迟，RAVEL 通过在滚动缓冲区中向前携带部分去噪的未来动作，使近期动作可在单步去噪后即被执行。为避免因缓慢的 VLM 编码而阻塞，RAVEL 将 VLM 编码与滚动动作生成解耦，使动作专家能够利用最新可用的 VLM 上下文持续运行，同时轻量级快速观测通路（FOP）直接以当前观测为动作专家提供条件。在仿真和真实世界操作任务中，RAVEL 在保持底层 VLA 任务能力的同时，始终实现显著更低的响应延迟，从而支持高频且响应迅速的闭环控制。

## Abstract
Flow-based vision-language-action (VLA) models are highly effective for generalist robot manipulation, yet their reliance on computationally expensive VLM encoding and multi-step iterative action generation imposes a significant latency bottleneck. The resulting inference latency makes it difficult for robots to respond quickly, especially in dynamic environments. We address this limitation with RAVEL (Rolling Asynchronous VLA Enabling Low-Latency Control), an asynchronous inference framework that addresses the computational bottlenecks of both the VLM backbone and the action expert. To reduce the delay from multi-step action denoising, RAVEL allows near-term actions to be executed after a single denoising step by carrying partially denoised future actions forward in a rolling buffer. To avoid blocking on slow VLM encoding, RAVEL decouples VLM encoding from rolling action generation, allowing the action expert to operate continuously using the latest available VLM context, while a lightweight Fast Observation Pathway (FOP) directly conditions the action expert on current observations. Across simulated and real-world manipulation tasks, RAVEL consistently achieves substantially lower response latency while maintaining the task capability of the underlying VLA, enabling high-frequency and responsive closed-loop control.

# RAVEL 论文结构化总结

## 1. 核心问题与整体含义

- **背景**：基于流的视觉–语言–动作（VLA）模型（如 π0.5、X-VLA、GR00T N1 等）已成为通用机器人操作的主流范式。这类模型通常先由 VLM 主干编码观测，再由"动作专家"通过多步迭代去噪（flow matching）生成一段动作块（action chunk）。
- **核心瓶颈**：VLM 编码（单次前向即数十毫秒级）与多步去噪串行执行，导致端到端推理延迟很高。传统**同步推理**下机器人在每个动作块之间必须停顿等待；而**朴素异步推理**虽可重叠推理与执行，但新生成的块在执行时已与机器人实际状态不匹配，导致块间不连续。
- **已有工作的不足**：RTC、VLASH、FASTER、滚动去噪（rolling denoising）等只解决了"多步去噪延迟"或"块间连续性"的一部分，但 **VLM 编码带来的延迟仍是阻塞动作持续生成的瓶颈**。
- **论文定位**：提出 RAVEL（Rolling Asynchronous VLA Enabling Low-Latency Control），同时缓解 **VLM 主干** 与 **动作专家** 两个计算瓶颈，使机器人能够高频、连续、响应迅速地闭环控制。
- **整体含义**：论文主张"低延迟本身就是动态操作任务性能的一部分"——在动态环境中，减少推理延迟可直接转化为更高的任务成功率，而不仅是用户体验的改善。

## 2. 方法论

### 2.1 核心思想
- 用**滚动缓冲区（rolling buffer）** 让未来动作在不同噪声水平下被逐步去噪，使得每个控制步只需**一次动作专家前向**即可释放一个可执行动作。
- 将 **VLM 编码与动作生成解耦**为两个异步工作流：动作专家始终用"最新可用的 VLM 上下文"继续滚动去噪，不被 VLM 前向阻塞。
- 引入**时间偏移条件（temporal-offset conditioning）** 与**快速观测通路（FOP）**，补偿因上下文陈旧与执行延迟造成的时空错位。

### 2.2 关键技术与公式（文字描述）
- **滚动缓冲区**：设缓冲区长度 K，在控制步 $t_a$ 时缓冲区保存 K 个未来动作，第 k 个槽对应 $t_a+k$ 时刻执行，其流时间步为 $\tau_k = 1 - k/K$（越靠后的动作噪声越高）。一次动作专家前向将每个槽推进 $\Delta\tau = 1/K$，之后第一个动作到达 $\tau_0=1$（干净端点）被释放执行，剩余 K−1 个动作保留，并在末位追加一个高斯噪声初始化的新动作。
- **VLM 上下文**：记为 $c_{t_o} = E(o_{t_o}, s_{t_o}, \ell)$，即由观测、本体状态与语言指令经 VLM 得到（可为 KV cache 或 VLM 特征）。
- **时间偏移条件**：定义归一化偏移 $\delta_p = p/K$，其中 $p = t_a - t_o$ 为上下文年龄（观测捕获到动作执行的间隔），作为动作专家的额外条件信号，使其能"预测到未来某个执行时刻"的动作。
- **异步上下文更新**：VLM 与动作专家分离为独立 worker；同一 VLM 上下文可被多次滚动更新复用，直到新上下文可用。
- **快速观测通路（FOP）**：用轻量图像编码器（ConvNeXt-Base）加本体状态投影得到 $z_{t_a} = F(o_{t_a}, s_{t_a})$，通过**门控交叉注意力适配器**注入动作专家的部分层，使即将执行的动作能直接响应最新观测，无需等待 VLM 更新。
- **流式对齐训练（Streaming-Aligned Training）**：训练时采样观测时刻 $t_o$ 与偏移 $p$（$t_a = t_o + p$），用与推理一致的噪声剖面 $a^{\tau_k}_{t_a+k} = (1-\tau_k)\epsilon + \tau_k \hat{a}_{t_a+k}$ 构造缓冲区，并以槽级速度预测误差 $[v_\theta(A_{t_a}, \tau, c_{t_o}, \delta_p)]^{[k]} - (\hat{a}_{t_a+k} - \epsilon_{t_a+k})$ 的 L2 损失监督；FOP 特征在启用时一并输入。
- **相对动作的坐标转换**：当模型输出相对动作（相对当前机器人状态）时，缓冲区存储"归一化绝对目标"，每次更新前再转成相对动作，避免参考状态变化导致目标漂移。

### 2.3 与基线的架构适配
- π0.5：冻结 VLM 主干，训练动作专家、动作输入/输出投影、流时间步 MLP 及新增的时间偏移 MLP；$\delta_p$ 经 MLP 编码后与流时间步嵌入相加。
- X-VLA：冻结 VLM 与 soft prompt，训练动作 Transformer 与动作头；$\delta_p$ 与噪声动作、本体状态、流时间步嵌入拼接后送入动作编码器。
- DynamicVLA：偏移与动作、流时间步嵌入拼接，其正弦嵌入通过门控残差适配器调节动作 token。

## 6. 主要结论与发现

- **保持操作能力**：在 LIBERO 与 RoboTwin 2.0 上，RAVEL 成功率与基线持平或略升（LIBERO：π0.5 96.5→97.8，X-VLA 95.9→95.8；RoboTwin：π0.5 44.3→46.8，X-VLA 65.1→66.8），说明滚动推理不会牺牲原有能力。

- **动态任务大幅提升**：
