## 摘要
视觉-语言-动作（VLA）策略会反复调用推理来控制机器人，因此GPU能耗成为任务执行中反复产生的成本。然而，若数值误差导致失败增加，或较慢的推理延长执行时间，降低每次推理调用的能耗未必能降低每个成功任务的能耗。因此，我们以每个成功任务的GPU能耗为目标，同时保持任务成功率，并将推理延迟增加控制在10%以内。我们的方法基于两个观察：量化敏感度因动作类别、模型层以及权重与激活而异；数值精度会改变工作负载，从而改变有利的GPU工作点。我们提出ActTune，一个动作感知框架，它将逐层精度分配与依赖于工作负载的GPU工作点选择相结合，并在所请求的频率—功耗上限对上进行选择。一个轻量级决策树直接从配置动作误差中学习其分裂和叶节点精度配置，然后在每次策略调用前选择精度。控制器预测下一工作负载，并使用在延迟预算下校准的查找表异步应用所选GPU工作点。一个共享的常驻量化权重库使得配置切换无需权重重建或额外策略评估。在终身机器人学习基准LIBERO上，ActTune相对于当前最优方法将平均任务成功率最多提升2.3%。相对于原始BF16实现，其推理速度最高提升2.02倍，并借助GPU工作点自适应，将每个成功任务的能耗最多降低76.8%。

## Abstract
Vision-language-action (VLA) policies repeatedly invoke inference to control robots, making graphics processing unit (GPU) energy a recurring cost of task execution. Reducing energy per inference call, however, may not reduce energy per successful task if numerical errors increase failures or slower inference prolongs execution. We therefore target GPU energy per successful task while preserving task success and keeping the inference-latency increase within 10\%. Our approach builds on two observations: quantization sensitivity varies across action classes, model layers, and weights versus activations; and numerical precision changes the workload, shifting favorable GPU operating points. We introduce ActTune, an action-aware framework that connects layer-wise precision allocation with workload-dependent GPU operating-point selection over requested frequency--power-cap pairs. A lightweight decision tree learns its splits and leaf precision configurations directly from configuration action errors, then selects precision before each policy call. The controller forecasts the next workload and applies the selected GPU operating point asynchronously using a lookup table calibrated under a latency budget. A shared resident quantized weight bank enables configuration switching without weight reconstruction or additional policy evaluations. On LIBERO, a benchmark for lifelong robot learning, ActTune improves mean task success by up to 2.3\% relative to state of the art. Relative to the original BF16 implementations, it delivers up to $2.02\times$ faster inference and, with GPU operating-point adaptation, reduces energy per successful task by up to 76.8\%.

## 1. 核心问题与整体含义

- **研究背景**：视觉-语言-动作（VLA）模型需要反复调用推理来控制机器人，因此 GPU 能耗是任务执行中反复产生的成本。对电池供电机器人而言，降低推理能耗有助于延长续航。
- **核心问题**：单纯降低“每次推理调用”的能耗，并不必然降低“每个成功任务”的能耗。原因包括：
  - 数值误差（如量化误差）可能导致任务失败率上升；
  - 推理变慢会延长任务执行时间，抵消功率降低带来的节能效果。
- **目标定义**：以**每个成功任务的 GPU 能耗**为目标，同时保持任务成功率，并将推理延迟增加限制在 **10%** 以内。
- **关键观察**：
  - 量化敏感度随**动作类别、Transformer 层、权重/激活**不同而显著变化。例如接近目标阶段可容忍误差，最终对齐阶段需要更高精度。
  - 数值精度会改变工作负载，从而改变有利的 GPU 工作点。不同精度（BF16、W4A8、W4A4）对应的最优频率—功耗上限组合不同。
- **整体含义**：ActTune 将**动作感知的逐层精度分配**与**负载相关的 GPU 工作点选择**联合起来，在保持闭环任务成功率的同时降低成功任务能耗。

## 2. 方法论：核心思想与关键技术

### 2.1 总体框架

- ActTune 是一个动作感知框架，分为两阶段：
  - **精度选择**：在每次策略调用前，根据当前本体感觉和前一预测动作块，选择逐层权重/激活精度配置。
  - **GPU 工作点选择**：根据精度配置带来的工作负载，选择请求频率 \(f\) 与功耗上限 \(p\) 组成的 GPU 工作点 \(u=(f,p)\)。
- 目标：在平均推理延迟增加不超过 10% 的约束下，最小化成功任务能耗。
- 关键设计：**共享常驻量化权重库**支持配置切换，无需重建权重，也无需为每个叶节点存储完整模型副本。

### 2.2 动作感知精度选择

- **决策树选择精度**：
  - 输入特征 \(x_t = [\phi(A_{t-1}, m_{t-1}); s_t]\)，包含当前本体感觉 \(s_t\)、前一预测动作块 \(A_{t-1}\) 的运动/夹爪特征及夹爪 margin。
  - 树将动作上下文划分为若干决策区域，每个叶节点存储一个精度配置 \(q_k\)。
  - 在线选择叶节点 \(k_t=g(x_t)\)，读取配置 \(q_t=q_{k_t}\)，无需额外策略调用。
- **校准损失**：
  - 对每个校准观测，比较候选配置输出动作 \(A^q_i\) 与 BF16 参考动作 \(A^{ref}_i\)。
  - 损失包含连续动作绝对误差与夹爪不一致项，夹爪项权重为 \(\lambda_g=0.1\)。
  - 优化目标为在叶节点数 \(K\) 约束下最小化加权拟合损失。
- **树结构学习**：
  - 离线从配置动作误差中学习分裂条件和叶配置。
  - 通过损失下降分裂生长树，再用自底向上动态规划获得给定叶节点数的最优拟合子树。
  - 用验证动作损失和 CPU 路由成本选择树复杂度，最终实验采用 3 个叶节点。
- **共享权重库**：
  - 校准选择可切换矩阵及其精度选项，形成配置集 \(Q\)。
  - 多数矩阵共享一个常驻版本；每个叶节点选择配置，多个叶可共享同一配置。
  - 使用 AWQ 式激活引导通道缩放和输出行裁剪，并以动作 Jacobian 加权重建误差排序层精度分配。
  - 在权重、激活和常驻存储预算约束下，贪心分配 W2/W4/W8 与 A2/A4/A8 组合。

### 2.3 GPU 工作点选择

- **离线 profiling**：
  - 固定权重库和精度选择器，对每个区域—配置对 \((k,q)\) 测量不同 \((f,p)\) 下的能量和延迟。
  - 保留能保持参考动作并通过内存检查的工作点。
  - 选择查找表 \(h^*\)：估计 GPU 能耗最低，且平均推理延迟相对固定参考工作点增加不超过 10%。
- **在线使用**：
  - 每次推理后，控制器预测下一决策区域和精度配置。
  - 查表得到对应 GPU 频率与功耗上限，并在两次调用之间异步应用。
  - 下一次推理期间保持该工作点固定。
  - 预测错误时，已准备的工作点继续生效；精度选择使用当前观测。

### 2.4 整数内核执行

- 低比特线性层不重建稠密权重：
  - 权重和激活均 ≤4 bit 时使用 INT4×INT4 Tensor Core 内核；
  - 含 8 bit 权重或激活时使用 INT8×INT8 内核；
  - 均使用 INT32 累加。
- W2/W4 权重保持打包，在内核中符号扩展至 INT8 tile。
- INT4 内核使用 CUDA 实现，包含打包操作数、形状相关 tile、异步拷贝、双缓冲共享内存和 fragment 复用。
- INT8 内核使用 Triton，包含合并权重布局、tile 局部解包和软件流水线。
- 融合激活量化与 GEMM epilogue，减少内核启动和中间内存流量。
