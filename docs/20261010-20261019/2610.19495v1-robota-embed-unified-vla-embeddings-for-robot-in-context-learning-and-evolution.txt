Abstract: Retrieving useful context for a robot requires matching not only its task, but also its current
stage of execution and the continuation that should follow. We introduce Robota-Embed, to our knowledge
the first vision–language–action (VLA) embedding model to jointly encode all three modalities in both
current-state queries and recorded future continuations. Predictive retrieval training aligns these endpoints
for physical-experience retrieval, and the resulting representation retrieves historical continuations as context
at inference time. We construct a multi-source corpus of 1,695,684 cleaned training anchors and introduce
Robota-Embed-Bench, which evaluates 4,000 queries against a shared 8,000-entry gallery. Our model achieves
47.33% clip-level and 81.77% episode-level R@1, surpassing action-free Gemini Embedding 2 by 22.09 and 33.47
percentage points. Across controlled retrieval studies, removing native action degrades retrieval more than
removing vision, indicating that execution information is a central part of the retrieval key. We then study
how this shared retrieval space transfers beyond retrieval metrics through two complementary applications.
Embed2ICL uses retrieved experience for training-free and training-based policy conditioning, increasing
success from 47.0% to 56.3% in DROID-Sim and from 86.4% to 92.8% on the LIBERO difficult subset. Both
interfaces also improve task progress in real-robot evaluations. Embed2Evolve uses execution feedback to grow
task-local memory and refine how retrieved context is used around a frozen GPT-6 Astra policy. Across five
ManiSkill tasks, it achieves 68% success, compared with 24% for GPT-6 Astra Direct and 33% for a harness
independently evolved with Omni-Embed-Nemotron-3B under the same protocol. Relative to the latter, it
uses approximately 79.5% fewer policy tokens per test rollout. Together, these results show that a unified,
action-aware retrieval space can support both robot in-context learning and task-local context evolution.

Robota-Embed: Unified VLA Embeddings for Robot In-Context Learning and Evolution
1. Introduction
Robot policies increasingly use experience supplied in context. GEN-1.5 [1] and S1 [2] demonstrate Robot
In-Context Learning from sensorimotor or video examples. In our experiments, GPT-6 Astra [3] generates
robot actions from observations and execution history. These capabilities make experience selection part of
the control problem. Demonstration-conditioned world action models (WAMs) need useful existing examples;
policies acting repeatedly must organize accumulated experience. Both raise a representation question: how
should physical experience be represented for task- and stage-sensitive retrieval?
Task similarity alone is insufficient. Reaching toward a bowl and withdrawing after placement can share
objects and an instruction yet require different continuations. Language specifies the goal, vision the interaction
state, and native action the ongoing motion. The retrieval endpoints have different temporal roles: the
query describes the present, whereas a candidate records what followed an earlier interaction. Predictive
retrieval therefore requires sensitivity to task intent and execution stage: the goal is an appropriate recorded
continuation, not simply a similar scene.
General-purpose embeddings align vision and language [4, 5, 6], while action-aware metric learning connects
perception or language with behavior [7, 8]. We introduce Robota-Embed, a unified vision–language–action
(VLA) embedding model for physical-experience retrieval. To our knowledge, it is the first to jointly encode
all three modalities in both current-state queries and recorded continuations. Each endpoint yields one
vector, so native action informs retrieval itself. Source-specific projectors handle heterogeneous action formats.
Retrieval training combines predictive alignment, multimodal grounding and discrimination, and representation
regularization.
We construct a multi-source training corpus and introduce Robota-Embed-Bench, with 4,000 queries
and 8,000 gallery candidates spanning human, simulated, and real-robot experience. Nearby same-episode
clips distinguish finding the right experience from locating its recorded continuation. Across four sources,
Robota-Embed achieves 47.33% clip-level and 81.77% episode-level R@1. Native action adds information
beyond text and images: with backbone, data, and training budget matched on DROID, adding action raises
clip-level R@1 from 59.8% to 78.7%. Complementary retraining and query-masking studies examine which
information the representation learns and uses.
Figure 1 connects retrieval to demonstration conditioning and memory-based interaction. Embed2ICL
supports robot in-context learning through two policy interfaces. For DreamZero [9], retrieved videos initialize
the visual cache without policy updates.
For Fast-WAM [10], we fine-tune the policy to condition on
precomputed Context Tokens from retrieved demonstrations. Both interfaces improve simulation task success
and real-robot task progress. Random-reference controls show that useful context depends on reference
selection.
Embed2Evolve extends retrieval to context management for agentic robots. Repeated attempts grow
task-local memory, while execution feedback refines retrieval, refresh, and retained-history settings around
a frozen GPT-6 Astra policy. Policy and embedding weights remain fixed. Across five ManiSkill tasks, the
selected context harness raises success from 24% with Direct to 68%, using 43.7% fewer policy tokens per
test rollout. To examine the retrieval model’s role, we independently repeat evolution with Omni-Embed-
Nemotron-3B from the same initial memory under the same search protocol. Its harness reaches 33% success;
Embed2Evolve uses approximately 79.5% fewer tokens than this baseline. Token averages include failed tests
and exclude development.
We make four contributions.
• Robota-Embed. A unified embedding model that jointly encodes vision, language, and native action at
both endpoints for predictive physical-experience retrieval.
• Data and evaluation. A multi-source training corpus, Robota-Embed-Bench, and controlled studies of
temporal precision, representation learning, and native action’s contribution beyond vision and language.
• Embed2ICL. Training-free and training-based interfaces that turn retrieved demonstrations into useful
policy context, evaluated in simulation and on real robots.
• Embed2Evolve. Embedding-guided memory and context evolution around a frozen policy, improving
success and token efficiency under matched comparisons of retrieval embedding models.

2. Related Work
Multimodal and action-aware embeddings.
CLIP aligns images with language [4]; Perception Encoder
and InternVideo2 extend vision–language representation learning to video [11, 12]. Unified vision–language
embeddings support image and video retrieval in one space [6, 13, 14, 15, 16]; ImageBind [5] includes additional
sensory modalities. Deep Multimodal Embedding [7] and CLASP [8] align language or perception with action.
VLA-R [17] embeds visual–language queries and action-token candidates in a shared space, while RADAR [18]
reuses VLA-policy features for retrieval. Robota-Embed jointly encodes vision, language, and native action at
both retrieval endpoints: the current state and the recorded future clip.
Physical-experience retrieval.
Action can enter the retrieval key or the content returned to the policy.
ROSER [19] searches proprioceptive sequences; RAEA [20], REGENT [21], and RICL [22] return actions
selected through action-free keys. Zeva [23] indexes action–effect evidence, whereas RADAR [18] uses policy
features. MemER [24] selects rollout keyframes; Retrieve-Reason-Act [25] indexes visual manuals. Robota-
Embed includes native action in both query and candidate keys, so motion informs the similarity comparison
itself (Table 33).
Robot In-Context Learning and Evolution.
GEN-1.5 [1] conditions on a sensorimotor example; S1 [2],
Zero-WAM [26], and HOST [27] use supplied video. R+X [28] retrieves human-video clips and converts
them into keypoint and hand-trajectory context. Embed2ICL uses Robota-Embed to select experience for
training-free and training-based WAM conditioning. Reflexion [29] stores verbal reflections in episodic memory,
using feedback to improve later trials without updating model weights. In robotics, Zeva [23] retrieves
action–effect evidence across retries within an episode, resetting memory for each new episode. Embed2Evolve
performs in-context evolution: it grows task-local memory across development episodes and refines retrieval,
refresh, and history settings around a frozen policy. Evaluation uses the selected memory and context settings
without further changes on fresh task initializations.

Retrieval-oriented training.
We train with predictive alignment, multimodal grounding, and repre-
sentation regularization. Structured parsing and deterministic rules supply weak labels. The supervision
distinguishes exact continuation identity from broader task compatibility; a different clip ID alone does not
establish a valid negative. Native action is learned within the fused representation, with modality swaps
encouraging sensitivity to motion without requiring action-only matching to an exact future clip.

4.1. Unified VLA Retrieval on Robota-Embed-Bench
Protocol and models.
Eight action-free baselines search the shared gallery (Section 3.3). CLIP-style
models retrieve video from text; unified VL models also use visual queries (Table 1). We use each model’s
supported interface. The retraining studies in Section B.4 use the same DROID data splits and training
budgets for the compared model variants.
Main results.
Robota-Embed achieves 47.33% clip-level and 81.77% episode-level R@1. The strongest
baselines, Gemini Embedding 2 and Omni-Embed-Nemotron-3B, reach 25.24% and 48.59%, respectively.
Robota-Embed improves on them by 22.09 and 33.18 percentage points.
Gains over unified VL baselines are largest on LIBERO and RoboMIND-FD (Section B.2). Episode retrieval
does not resolve temporal localization: on EgoDex, episode/clip R@1 is 87.06/36.70%, versus 99.88/74.10% on
DROID. Finding a relevant experience is easier than locating its paired continuation, the target of predictive
retrieval.
Benchmark validity.
Masking candidate text before fusion and recomputing embeddings lowers clip-
level R@1 from 47.33% to 12.78%, confirming that the model uses language. Restricting candidates to
the same instruction still gives 47.62% R@1, so the model also distinguishes continuations that share an
instruction. Within same-instruction galleries, Robota-Embed achieves 38.60% and 40.10% R@1 on LIBERO
and RoboMIND-FD, compared with random-ranking rates of 1.90% and 0.24%, respectively. High-𝑘recall
approaches saturation in the smaller EgoDex and DROID pools. Tables 12 and 13 give the full aggregate
results, per-source candidate counts, and random baselines.
Index-size scaling.
Expanding the precomputed gallery from 1M to 15M entries increases query encoding
plus retrieval latency from 160.36 to 195.17 ms on one NVIDIA A100 (Table 22). At 15M, Top-10 search
alone takes 37.47 ms. These timings exclude time spent on SAM3 preprocessing, reference reranking, and
downstream policy execution (Section B.6).

4.2. What Makes Predictive Retrieval Work?
The controlled studies separate representation adaptation from input use. On the shared four-source benchmark,
a frozen Cosmos3-Edge readout reaches only 0.65% clip-level R@1, whereas retrieval training reaches 47.33%
(Table 15). On the matched DROID split, a learned head over frozen features reaches 13.8%, compared with
78.7% when the backbone and head are adapted (Table 16). Predictive alignment already places the paired
continuation near the top at 75.6% R@1 and 100.0% R@10; representation regularization raises R@1 to 77.0%,
and multimodal grounding and discrimination further raise it to 78.7% (Table 17). The added objectives
therefore refine top-rank ordering rather than merely broad recall.
Action is the most consequential non-language input in both controlled views. Retraining without action
lowers R@1 by 18.9 percentage points, versus 1.9 points without vision (Table 19); with the final model and
gallery fixed, masking query action or vision lowers clip R@1 by 27.25 or 24.33 points (Table 20). These
interventions answer different questions: retraining measures what the remaining modalities can relearn,
whereas masking measures reliance under an input shift. Thus the small no-vision retraining gap does not
imply that the final model ignores vision. SAM3 interaction crops provide a further, modest localization gain
over full frames, 78.7% versus 77.9% R@1 (Table 18). Appendix B reports each intervention as a separate
table and conclusion.

6. Discussion
Retrieval quality has two levels.
Episode recall measures experience identification; clip recall measures
continuation localization. Their gap shows that matching a task and embodiment need not identify the
execution phase. Same-instruction evaluation and candidate-text masking probe temporal discrimination and
target-language use beyond episode identification.
The modalities play complementary roles.
Language specifies the task, action supplies motion and
phase, and vision localizes the interaction. Action adds information beyond vision and language. However,
retraining permits adaptation to remaining inputs, whereas masking perturbs learned fusion. The no-vision
retraining/masking gap supports a joint VLA key, not a universal modality ranking. Accordingly, masking
characterizes the trained model’s use of each input, not the attainable performance of separately trained
unimodal systems.
Retrieved context is useful only through a compatible interface.
Random references hurt DreamZero
relative to no warm-up (36.0% versus 47.0%), whereas Robota-Embed’s raw retrieval and reranked Embed2ICL
reach 50.3% and 56.3%. Fast-WAM gains from retrieved rather than random Context Tokens under fixed
policy weights (92.8% versus 88.0%). More context is not inherently better: reference selection, temporal
content, and conditioning jointly matter, without isolating each component’s causal contribution.
Memory size and policy context are different resources.
Embed2Evolve can grow memory while
retaining less history and refreshing less often. Independent evolution with Omni-Embed-Nemotron-3B
compares discovered memories and harnesses, not a fixed-harness encoder swap. Token and reference-cost
metrics cover all test rollouts; decision/time comparisons use shared successes. Fewer policy calls need not
mean fewer control ticks or shorter robot motion.
Future work.
Future work will extend Robota-Embed to more robot embodiments with diverse kinematics,
native action spaces, and control interfaces. We will also explore variable-length retrieval that adapts the
temporal extent of recorded continuations to the task and execution stage, rather than using a fixed four-second
window. The goal is to retrieve only the duration of experience needed for the current interaction.
7. Conclusion
Robota-Embed jointly encodes task intent, visual state, and native action for physical-experience retrieval;
action improves retrieval beyond language and vision. This shared space supports Embed2ICL conditioning
and Embed2Evolve memory evolution. Under matched settings, Embed2Evolve’s success and efficiency gains
show that representation shapes both retrieved context and the harness around a frozen policy.

We generate weak labels through structured parsing and deterministic rules.
Qwen3-VL-8B-Instruct [38] parses task instructions into operation names and object roles using non-sampling

Before similarity-based
mining, we determine eligibility for 𝒩(𝑖) using four pairwise conflicts: Task conflict preserves object roles but

interaction-object category. Action conflict shares task and objects but differs in the current-action primitive
or future-action phase. Joint conflict changes both task and objects.
For same-episode action negatives, future windows with temporal intersection-over-union greater than 0.25
are treated as near-duplicates and excluded. Cross-episode action negatives must additionally differ in future
gripper phase. These checks filter the action-conflict class; semantically compatible, uncertain, or potentially
duplicate candidates are masked out of the negative set. A different clip ID alone is therefore insufficient to
make a pair negative.
Current-action primitives are obtained by scale-standardizing the domain-normalized action and discretizing
each coordinate at thresholds −0.5 and +0.5. Future-action phase combines the dominant motion direction,
the timing of peak motion, and changes in gripper state. To compare future actions, we sample 16 time points
and concatenate the per-coordinate means, standard deviations, and first-to-last differences. We compare
these descriptors using scale-normalized RMS distances.

B. Robota-Embed-Bench Evaluation and Diagnostics
B.1. Robota-Embed-Bench: Composition and Evaluation
EgoDex, DROID, LIBERO, and RoboMIND–Franka-dual each contribute 1,000 held-out queries from 800
unique episodes. The shared 8,000-item gallery contains 2,000 candidates per source: 1,000 paired future clips
and 1,000 nearby same-episode clips. Nearby clips often share the positive’s instruction, objects, and visual
content, requiring precise temporal localization.
The four sources contain 591, 800, 39, and 5 distinct task-instruction strings, respectively, covering human
experience, simulation, and single- and dual-arm robots. DROID and LIBERO also support the downstream
ICL studies, evaluated separately from retrieval.
Clip-level retrieval assigns one positive to each query: its uniquely paired future four-second window.
Episode-level retrieval treats any indexed window from the same source-scoped episode as relevant. Episode-
level metrics average query outcomes within each episode, then equally over the 800 episodes per source and
the four sources, giving each episode equal weight regardless of its query count. In total, the benchmark
contains 4,000 queries and 3,200 episodes. Training, validation, and original test partitions are separated by
complete episode, session, and content identity before dense anchoring. Benchmark episodes are excluded from
training; task, object, and embodiment categories may overlap across partitions. Every target is strictly later
than its paired query anchor. Ranking uses cosine similarity on L2-normalized embeddings, without reranking.
We evaluate the final Robota-Embed checkpoint at training step 26,275, the last step of retrieval training.
Baseline input interfaces.
Robota-Embed queries combine instruction, a SAM3 object zoom, and synchro-
nized action; gallery entries combine instruction, future video, and future action. Omni-Embed-Nemotron-3B
and Qwen3-VL-Embedding-2B use instruction and the uncropped current frame as the query, and instruction
and the 16-frame future clip as the candidate. CLIP, Perception Encoder, and InternVideo2 use the instruction
to retrieve the future video clip. Gemini Embedding 2 and VLM2Vec-V2 likewise use instruction plus
the original, uncropped current image as the query, without action input, and instruction plus the future
four-second video as the gallery entry. For Gemini Embedding 2, we upload a video assembled from 16
frames and obtain normalized 768-dimensional vectors. VLM2Vec-V2 receives the 16 frames directly and uses
last-token pooling followed by L2 normalization, producing 1,536-dimensional vectors. Both are evaluated on
all 4,000 queries and 8,000 gallery entries. The released WeMM-Embedding-2B model is evaluated zero-shot
with instruction and the uncropped current frame as the query, instruction and the 16-frame future clip as
the candidate, and L2-normalized 2,048-dimensional outputs. Each external baseline is evaluated through its
supported input interface. The controlled DROID study isolates modality choices with matched training data,
backbone architecture, and optimization budget.
Frozen Cosmos3-Edge feature baseline.
The frozen Cosmos3-Edge control uses the same query and
target fields and native action projectors as Robota-Embed. We extract dense action-token features after the
final RMSNorm of layer 28, before the action-output projection. Temporal averaging and L2 normalization
produce a 2,048-dimensional VLA-conditioned backbone readout.

C. Embed2ICL Implementation and Supplementary Results
This section covers DreamZero’s training-free video-cache warm-up and Fast-WAM’s training-based Context

C.1. DreamZero-DROID Reference Warm-Up
Embed2ICL initializes frozen DreamZero-DROID’s cache with a retrieved and reranked video (Figure 9).
Both retrievers use the same GPT-5.6 sol Reranking Agent. All reference conditions use four-second videos.
Each Embed2ICL reference contains three synchronized streams at 15 Hz for four seconds (60 frames per
view): 45 frames before the detected final gripper release, the release frame, and 14 frames after it. All three
streams serve as video-only policy input. Embed2ICL performs one warm-up per applicable task phase and
issues eight reference-conditioned policy requests. Live observations then update the rolling cache. The source
episode and temporal window remain fixed across all trials for a task, so the experiment evaluates conditioning
on a selected task reference. We evaluate the three tasks in Table 2. No warm-up, random reference, both
retrievers’ top-1, and both reranked conditions each use 100 trials per task, totaling 300 per condition. All
share the released DreamZero-DROID policy; only the test-time video reference changes. The top-1 conditions
select an episode and recut a four-second reference from its successful stage.
C.2. DreamZero Reference and Interface Analysis

D. Embed2Evolve: Harnesses, Development, and Evaluation
Embed2Evolve accumulates completed attempts in task-local memory and searches for a recipe for using
that memory during control. Online retrieval ranks individual memory anchors; development compares entire
context configurations. The two decisions use different criteria. The policy and embedding models remain
fixed throughout.
D.1. Policy and Memory Interfaces
Matched embedding-model design.
We compare Robota-Embed with Omni-Embed-Nemotron-3B [6] by
replacing only the retrieval embedding model and developing each condition independently. Both use the
same GPT-6 Astra policy, prompt, initial memory, development and test seeds, candidate-generation rules,
and stopping criteria. Retrieved memories supply the same RGB, action, and feedback fields to the policy.
Both evolved systems use the full memory interface; the random-history baseline supplies only RGB.
At each decision, GPT-6 Astra receives all current RGB views, robot state, execution feedback, recent
action/feedback history, and external context when available. It proposes end-effector target poses and
gripper commands, which are validated and executed by a fixed IK/controller. Table 26 gives the runtime
and budgets. The four single-arm tasks use base_camera, vision_side, vision_top, and vision_wrist;
TwoRobotStackCube uses base, side, top, and separate left/right wrist cameras. The policy observes all four
or five views, respectively, at every decision.

to that robot’s base frame and executed by the native IK/PD controller. In the two-arm task, the other arm
holds its measured pose at the start of the primitive. The shared prompt requires explicit targets, without
hidden tool calls or automatic execution until a target is reached. It restricts observations to RGB, the robot’s
own state, the instruction, and public actions and feedback; object poses, private simulator state, and task
code are excluded. A gripper command does not establish grasp success, nor does an IK target establish

Stopping and freezing.
Stopping tracks the Pareto frontier of (𝑁ℓ, −𝐿ℓ, −𝑇ℓ). A point dominates another
when it is no worse in all three coordinates and better in at least one. A candidate adds a frontier point only
if no existing point dominates it and its coordinates are not already present.
After at least three eligible rounds under the current transport version, two consecutive rounds without a
new frontier point trigger stopping. A separate cap allows at most eight numbered development rounds per
task, including earlier transport versions; baseline collection and formal testing do not count toward it. Any
started round must complete ten valid trials.
For each embedding model, formal testing freezes the winning configuration and the memory bank from
that round. Test outcomes do not enter selection. The two conditions develop independently and can produce
different banks and recipes. The comparison measures the embedding model’s contribution through evolution,
not a replacement within one final harness.
