## 摘要
近年来，视觉-语言-动作模型的进展激发了人们对水下具身智能日益增长的兴趣。然而，这些模型对大规模交互数据的依赖限制了其在水下的适用性，因为水下数据采集成本高昂且十分稀缺。为应对这一挑战，我们提出了 AquaCap，一种面向自主水下导航与操作的免训练 Code-as-Policy 框架。AquaCap 采用双层智能体，将任务指令和环境观测转化为条件感知的规划和可执行控制程序。结构化感知随后在退化的水下条件下为智能体提供语义、几何和可靠性感知的观测。故障感知记忆可诊断失败动作，并支持闭环重规划和代码修订。该设计无需特定任务训练或参数更新即可实现在线适应。AquaCap 在仿真中取得了 66.43% 的成功率。真实世界实验进一步展示了使用 ROV 进行自主抓取和物体运输，包括对受水动力扰动而位移的目标进行操作。

## Abstract
Recent advances in vision-language-action models have stimulated growing interest in underwater embodied intelligence. However, their reliance on large-scale interaction data limits their applicability underwater, where data collection is costly and scarce. To address this challenge, we present AquaCap, a training-free Code-as-Policy framework for autonomous underwater navigation and manipulation. AquaCap employs a dual-layer agent that translates task instructions and environmental observations into condition-aware plans and executable control programs. Structured perception then provides the agent with semantic, geometric, and reliability-aware observations under degraded underwater conditions. A failure-aware memory diagnoses unsuccessful actions and supports closed-loop replanning and code revision. This design enables online adaptation without task-specific training or parameter updates. AquaCap achieves a 66.43% success rate in simulation. Real-world experiments further demonstrate autonomous grasping and object transport with an ROV, including the manipulation of targets displaced by hydrodynamic disturbances.

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体框架
- **核心思想**：把水下任务分解为**可验证的阶段**，每个阶段用生成的 Python 程序执行，执行后通过新鲜观测验证物理结果，失败则进行代码修订或任务重规划，形成"规划—执行—反思—自校正"闭环。
- **三大组件**：AquaCap-Agent（规划与代码生成）、AquaCap-Perception（结构化感知）、AquaCap-Memory（故障感知记忆）。
- **关键假设**：命令完成不等于目标达成。水下车辆漂移和目标运动可能使中间结果在下一动作开始前失效，因此必须验证物理结果并全程纠错。

### 2.2 AquaCap-Agent（双层智能体）
- **动机**：现有 CaP 与语言引导系统常将任务规划与动作生成耦合在单一推理管线中，导致规划错误与实现错误难以区分，局部编码失败会破坏整个任务；且常假设生成动作按预期执行，缺乏对物理结果的验证。
- **设计**：
  - **Policy Agent（策略智能体）**：负责规划与修订任务，输出有序计划 Π；每个动作指定**目标、前置条件、后置条件、时间预算**，条件以布尔、数值或类别检查形式引用观测字段（例如"接近"动作要求执行前目标可见、执行后处于指定距离内）。
  - **Coding Agent（编码智能体）**：为每个动作生成 Python 程序，综合动作定义、观测、API 文档与检索到的修正 h。
  - **静态验证**：检查语法和 API 使用；**执行沙箱**：强制运动限制、权限和动作时间预算；无效代码允许有限次重写，仅验证通过的代码才执行。
- **算法流程（Algorithm 1）**：
  1. 输入指令 l、机器人 API、时间与恢复预算；初始化 M ← ∅，o ← Perceive()；初始化场景描述符；Π ← Policy(l, o)。
  2. 当 Π 有未完成动作且时间未尽：A ← Current(Π)；o ← Perceive()；检查传感器有效性与前置条件，传感器故障即停止。
  3. 前置条件通过则 h ← Retrieve(M, A)，r ← CodeAndRun(A, o, h)，再 o ← Perceive()。
  4. 用 r、o 及下一动作需求验证 A；将结果、证据与诊断存入 M；不可恢复故障即停止。
  5. 全部适用检查通过则 Π ← Advance(Π)；否则若尚有恢复预算则使用一次尝试：局部修复且重写次数未用尽则保留 A 做代码修订，否则 Policy 用失败证据与 h 修订剩余计划。
- **关键点**：正常结束的程序仍可能验证失败（如对齐动作完成但目标已移出位置，不足以支撑抓取）；前置条件未满足也进入同一恢复路径，但不执行动作。

### 2.3 AquaCap-Perception（结构化感知）
- **语义目标识别**：给定指令与 RGB 图像，VLM 识别目标并提示 SAM3 分割，产生掩码、目标可见性与置信度，将语言指令链接到后续几何估计所用物体。
- **近场几何估计**：
  - 腕部深度图像中的局部表面凸起提供互补掩码；对选定掩码 M，有效像素集合 ΩM 经配准深度 D 与相机内参 K 映射为点云：
    - **公式 (1)**：P0 = { D(u)·K⁻¹·ũ | u ∈ ΩM, ũ = (ux, uy, 1)ᵀ }
  - 深度滤波与离群点去除得到观测点 P = {pj}；有效点不足则不产生几何估计。
  - 用配置的目标尺寸（长度 L、直径 d）构建参考模型；对类圆柱目标先用 **PCA** 估计初始中心与主轴，再用 **ICP** 对齐模型点 Q = {qk} 与观测点：
    - **公式 (2)**：(bR, bt) = argmin_{R∈SO(3), t∈R³} Σ_{j∈I} ‖pj − R·q_{c(j)} − t‖₂²
  - **公式 (3)**：bTBO = TBC · bTCO，将拟合的相机坐标系位姿变换到机器人基座坐标系。
  - 收敛性、拟合质量、可见范围、掩码大小与轴向决定估计是否被接受；几何输出为目标位置与主轴，**绕对称圆柱轴的旋转不可观测**。
- **结构化输出**：目标身份、距离、几何质量、相机状态、夹爪状态；这些字段同时支持故障诊断，且**不向 Policy 和 Coding 传递原始图像**。

### 2.4 AquaCap-Memory（故障感知记忆）
- 存储动作结果并在**当前试验内**复用修正，**不更新模型参数**；每条记录将动作与场景描述链接到结果及支撑证据，失败动作额外存储诊断原因与建议修正。
- 每次试验开始时 M 为空；检索使用任务、当前动作与初始场景描述符（目标类别、可见性等，源自开局观测并在试验期间固定）。
- 检索记录为 Policy 提供规划建议、为 Coding 提供实现约束（例如抓取失败可提示 Policy 重复对齐、Coding 降低接近速度或调整夹爪闭合）；当前观测仍决定目标几何并验证结果。

## 4. 实验结果与分析

### 4.1 仿真主结果
- **总体 SR**：AquaCap 在导航、抓取、运输、跟踪四类任务上总体优于 U0、OpenVLA-ft 与 CaP-Agent0。相对 CaP-Agent0 的提升主要来自**双层解耦 + 结果验证 + 故障记忆**；相对 U0 / OpenVLA-ft 的优势则体现为**免训练**条件下仍具备竞争力甚至更优，说明在数据稀缺的水下场景中，程序化组合预训练模型能力是可行的替代路径。
- **任务差异**：
  - **导航类**（Goto、Inspect、Scan）AquaCap 表现稳健，SPL 较高，说明结构化感知提供的目标可见性与几何质量字段足以支撑长时程导航与巡检。
  - **抓取类**是区分度最大的任务。带 **X** 标记的干扰任务（Pick red X / blue X）上，语义目标识别 + 掩码分割的组合使 AquaCap 能正确锁定同类别中的指定目标，而基线更易被颜色相近的干扰物误导。
  - **运输类**（Transfer red）中 SSR 反映抓取阶段的可完成性，AquaCap 的高 SSR 表明"命令完成 ≠ 目标达成"的验证机制有效抑制了"看似抓取成功、实则已滑脱/漂移"的隐性失败。
  - **跟踪类**（Follow boat）以 MTD 衡量，AquaCap 因可动态重规划与修订代码，能更好维持与运动目标的距离。
- **ASD**：AquaCap 在成功试验上的平均耗时通常不劣于基线，说明其恢复机制并未以显著的时间开销换取成功率；失败多集中于需要多次恢复预算的困难任务。

### 4.2 真实世界结果
- **抓取与抓取-运输**：在浮力自扶正、持续漂移旋转的目标上，AquaCap 完成了多次抓取与搬运投放，验证了**感知-规划-编码-验证**闭环在真实水动力学扰动下的可行性。
- **关键观察**：
  - 目标位姿在接近过程中不断变化，**绕圆柱对称轴的旋转不可观测**这一限制被"对齐—验证—再对齐"的迭代流程自然吸收。
  - 推进器尾流与机械臂扰动本身会推动目标，因此**验证必须使用新鲜观测**，任何基于旧观测的假设都可能失效——这直接支撑了论文的核心假设。
  - 无人工干预、每次试验 Memory 清零的条件下仍能运行，说明在线适应不依赖跨试验记忆积累。

### 4.3 消融实验结论
- **Single Agent vs. 双层**：合并规划与编码后，失败更难归因，局部编码错误会传播为整任务失败，SR 下降，恢复成功率降低——验证了**解耦规划与实现**对错误定位与局部修复的价值。
- **w/o Memory**：禁用记忆后，同类失败在后续阶段反复出现，恢复尝试更"盲目"，ASD 上升或 SR 下降——说明记忆的作用是**把一次性诊断转化为可复用的修正先验**，而非改变底层控制能力。
- **Single+NoMem**：性能最差，表明两项设计**互补**：解耦提供"可修复的粒度"，记忆提供"修复的方向"。
- **感知与验证的贡献**：结构化感知（目标身份、距离、几何质量、相机与夹爪状态）既是规划与编码的输入，也是故障诊断的证据来源；去掉结果验证后，程序正常结束但任务失败的隐性错误显著增加。

## 5. 讨论

### 5.1 主要贡献
- **免训练范式**：AquaCap 不更新任何模型参数，把预训练 LLM/VLM 作为运行时推理与代码生成引擎，为水下 VLA 提供了一条绕开大规模水下数据采集的方案。
- **双层规划-编码智能体**：显式分离"做什么"与"怎么做"，使规划错误与实现错误可区分、可分别修复。
- **结果导向的验证闭环**：以物理后置条件而非命令返回值为成功判据，应对水下漂移、目标运动与执行不确定性。
- **故障感知记忆**：在当前试验内复用诊断与修正，实现"经验加速"而不触及模型参数。
- **结构化感知接口**：向智能体暴露语义与几何字段而非原始图像，降低推理负担并统一了感知、规划与诊断的接口。

### 5.2 局限与边界条件
- **依赖 API 完备性**：系统的能力上界由机器人控制 API 决定；缺少对应原语的任务无法通过代码组合完成。
- **几何不可观测性**：类圆柱目标的轴向旋转不可观测，抓取姿态在对称轴方向存在自由度，可能影响需要特定夹持角度的任务。
- **感知脆弱性**：浊水、强散射、低照度会降低分割与深度质量，几何估计可能被拒绝而触发恢复，进而消耗时间预算。
- **LLM 依赖与成本**：云 API 带来延迟、费用与网络可用性风险；沙箱与静态验证虽提升安全性，但仍无法完全排除生成代码的边界行为。
- **评测规模**：真实实验为 10+10 次试验，虽具代表性但样本有限；仿真虽沿用标准基准，仍存在 sim-to-real 差距。

### 5.3 未来方向
- 引入**跨试验记忆**或轻量在线学习，使修正先验可积累。
- 增强感知在退化条件下的鲁棒性（多模态、主动感知、去散射）。
- 将安全约束、能耗与推进器限制更显式地纳入规划目标。
- 扩展到多机器人协作、长时程巡检与接触丰富操作（如阀门操作、插接、采样）。

## 6. 结论

AquaCap 提出了一个面向水下机器人的**免训练、代码即策略**框架：它把复杂水下任务分解为带前置/后置条件与时间预算的可验证阶段，由 Policy Agent 规划、Coding Agent 生成并沙箱执行 Python 程序，借助结构化感知获取语义与几何证据，并通过故障感知记忆在当前试验内复用修正。其核心洞察是——**命令完成不等于目标达成**，因此必须在每个阶段后用新鲜观测验证物理结果，失败则局部修复代码或重规划任务。仿真（Stonefish 上 20 个任务、四方法对比）与真实（浮力自扶正目标的抓取与运输、全程无人工干预）实验，以及 40 次试验的消融分析共同表明：解耦的双层智能体、结果验证与故障记忆三者互补，使系统在无任务特定训练的前提下具备在线适应能力，为数据稀缺的水下自主作业提供了实用且可解释的路径。
