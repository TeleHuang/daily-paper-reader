## 摘要
视觉-语言-动作（VLA）模型通过两阶段设计展现出强大的机器人操作能力：先是一个视觉-语言模型（VLM）阶段，随后是一个动作扩散Transformer（ADiT）阶段。由于机器人必须满足严格的安全服务等级目标（SLO），VLA推理本质上是延迟关键的。满足这些SLO需要高端GPU，但重量、成本和功耗约束使得无法在机器人上集成此类GPU。先前工作将VLA推理卸载到边缘服务器，由其在VLA模型上服务多个机器人。然而，当前VLA系统缺乏在多GPU服务器上、满足SLO的多请求、多模型执行支持，而现有多阶段模型服务系统针对吞吐量和跨独立GPU的阶段解耦进行优化，不适合VLA模型的毫秒级阶段。我们设计了Robion，这是首个面向多GPU边缘服务器上多机器人、多模型请求并满足SLO的VLA服务与管理系统。我们的服务引擎通过两条流在单个GPU内解耦VLM和ADiT阶段，动态限制VLM流上的SM，使ADiT总能找到SM与其并行运行，并通过在这些模型间共享这些流来共置多个模型，同时根据剩余SLO时间最少优先处理请求。我们的管理引擎支持在多GPU服务器上进行灵活的模型放置，并集成智能流量控制器，在所选放置方案下最大化每个模型的批处理，同时限制每个GPU的负载以满足SLO。对于单个模型，在满足98% SLO达成率的情况下，Robion可服务的机器人负载平均分别比vLLM-Omni（最广泛使用的多阶段服务系统）和Monolithic（将VLM与ADiT作为单一流水线运行）高6.7倍和1.5倍。在4-GPU服务器上服务8个不同模型的大规模实验中，Robion可在98% SLO达成率下最多服务64个机器人。

## Abstract
Vision-Language-Action (VLA) models show high robotic manipulation capabilities via a two-stage design: a Vision-Language Model (VLM) stage followed by an Action Diffusion Transformer (ADiT) stage. Since robots must meet strict Service-Level Objectives (SLOs) for safety, VLA inference is inherently latency-critical. Meeting these SLOs requires high-end GPUs, yet weight, cost, and power constraints preclude integrating such GPUs on-robot. Prior works offload VLA inference to edge servers that serve many robots on VLA models. However, current VLA systems lack support for multi-request, multi-model execution on a multi-GPU server under SLOs, while existing serving systems for multi-stage models are optimized for throughput and stage disaggregation across separate GPUs, which are ill-suited for the millisecond-scale stages of VLA models. We design Robion, the first VLA serving and management system for multi-robot, multi-model requests on multi-GPU edge servers that meets SLOs. Our serving engine disaggregates the VLM and ADiT stages within a GPU via two streams, dynamically restricting the SMs on VLM stream so ADiT always finds SMs to run alongside it, and co-locates multiple models by sharing these streams across them, prioritizing requests by least remaining SLO time. Our management engine enables flexible model placements on multi-GPU servers, and integrates an intelligent traffic controller that maximizes per-model batching under the chosen placement while bounding each GPU's load to meet SLOs. For individual models, Robion serves on average 6.7$\times$ and 1.5$\times$ higher robot load within 98% SLO attainment over vLLM-Omni, the most widely used multi-stage serving system, and Monolithic, which runs VLM and ADiT as a single pipeline, respectively. In a large-scale experiment of serving 8 different models on a 4-GPU server, Robion can serve up to 64 robots within 98% SLO attainment.

## 1. 核心问题与研究动机

- **背景**：物理 AI 与机器人工厂（BMW、Amazon、DHL 等）正大规模部署机器人集群，视觉-语言-动作（VLA）模型成为机器人操作（搬运、分拣、打包、装配）的核心基础模型。
- **核心矛盾**：
  - VLA 推理是**延迟关键型**负载，必须满足严格的服务等级目标（SLO），否则会导致任务失败、运动抖动、装配线停工等安全问题。
  - 满足这些毫秒级延迟需要高端 GPU，但受**重量、成本、功耗、散热**限制，高端 GPU 无法集成到机器人本体上；机器人端推理还会使电池续航下降约 45%。
- **解决思路**：在工厂内部署**本地边缘服务器**，通过 WiFi 7 等低延迟网络为多台机器人提供 VLA 推理服务。
- **现有系统不足**：
  - 现有 VLA 系统（ROSA、Kairos、Armory）只解决模型放置、任务级效率或请求调度，**不支持多请求、多模型、多 GPU 的并发执行与 SLO 保障**，且均将 VLM 与 ADiT 视为单一流水线。
  - 现有多阶段服务系统（vLLM-Omni、M*、SGLang-Omni）面向**吞吐量**优化、将阶段解耦到**独立 GPU**，且其"每个扩散步检查缓冲区"的开销在 VLA 毫秒级阶段上占比高达 30–35%，反而不如单流水线方案。
- **关键洞察**：VLA 模型仅 1–5B 参数（约 10GB 内存），远低于服务器 GPU 的 80–96GB 容量，因此**单卡共置多个模型**在成本上极具吸引力。

## 2. 方法论：Robion 系统设计

### 2.1 整体架构
Robion 由**服务引擎**（Serving Engine）和**管理引擎**（Management Engine）两大部分组成，是首个面向多机器人、多模型、多 GPU 边缘服务器且满足 SLO 的 VLA 服务与管理系统。

### 2.2 服务引擎（三大技术）

- **固定批次的 GPU 内阶段解耦**
  - 用两条异步 CUDA 流（一条 VLM、一条 ADiT）在单 GPU 内解耦两个阶段，使计算密集型的 VLM 与访存密集型的 ADiT 能并发处理独立请求，互补利用计算与显存资源。
  - 采用**固定批次大小**（仅在阶段开始时准入请求），避免连续批处理（continuous batching）在每个 ADiT 扩散步（1–2ms）的缓冲区检查与张量打包开销。
  - 使用 CUDA graphs 消除逐内核 CPU 启动开销；初始化阶段为每个「阶段 × 批次大小」组合预录制图，运行时按需回放。

- **锁步（Lockstep）执行 + 受保护动态 SM 分区**
  - **问题**：VLM 大内核的线程块会占满所有 SM，导致并发发起的 ADiT 小内核无法调度，二者被串行化。
  - **核心思想**：限制 VLM 流可占用的 SM 数量，保证 ADiT 始终能找到空闲 SM 并行执行。
  - **挑战**：动态调整 VLM SM 限制需要抢占正在运行的 VLM 阶段，会导致 CUDA graph 失效或阶段执行进度丢失。
  - **解决方案**：采用锁步执行——每个锁步内恰好运行一个 VLM 阶段（第 k 批）与一个 ADiT 阶段（第 k-1 批），SM 限制**只在锁步开始时设置一次**，避免运行中抢占。
  - **性能辅助动态 SM 限制**：离线 profiling 枚举所有 VLM/ADiT 批次大小组合（典型为 2 的幂次），穷举搜索使锁步总时间最小的 SM 限制值，存入查找表；运行时直接查表应用。实现上使用 CUDA Green Contexts（AMD 可用执行上下文）。

- **SLO 感知的双流多模型服务**
  - 所有共置模型**共享**同一条 VLM 流与同一条 ADiT 流；每个锁步内 VLM 流只执行某一模型的批次，ADiT 流执行同模型或不同模型的批次。
  - **理由**：① 同时运行多个 VLM 或多个 ADiT 会造成同类资源争用；② 单 VLM + 单 ADiT 的锁步结构使 Robion 能在每个锁步起点选择要调度的请求，从而实现 SLO 感知优先级。
  - **调度策略**：每个共置模型一个 FIFO 队列，采用**最早 SLO 优先（ESF）**——计算各队列队首请求的剩余 SLO 时间，选择剩余时间最少者出队。
  - 离线 profiling 扩展至跨模型对组合，复杂度为 O(U²·log(max_batch)²)，其中 U 为共置架构数，通常很小；同架构微调变体可复用 profiling 结果。

### 2.3 管理引擎（两大技术）

- **灵活的模型放置**：支持程序员配置模型在不同 GPU 上的共置、复制，或将 GPU 划分为互斥分组、每组仅服务单一架构的微调变体。

- **自适应流量控制器（整数规划）**
  - 目标：在机器人群体异构时，既提高每模型批处理量（集中流量），又限制单 GPU 负载以避免 SLO 违约。
  - **约束 (1)**：每个模型的机器人总数按 GPU 分配后求和等于 N_i：Σ_j r_ij = N_i。
  - **约束 (2)**：每 GPU 的负载饱和度不超过 1：Σ_i r_ij / C_i ≤ 1，其中 C_i 为该 GPU 服务模型 m_i 时的最大机器人数（初始化时通过基准测试确定，直到找到仍满足目标 SLO 达成率的最大值）。
  - **目标函数 (3)**：最小化所有 GPU 上不同模型对分配数的乘积之和：min Σ_j Σ_{i<k} r_ij·r_kj。该目标鼓励每个 GPU 尽量只服务单一模型（此时所有乘积项为 0），从而集中流量、提升批处理。
  - 用 Google OR-Tools 求解；若约束不可满足则提示程序员调整放置或增加 GPU。

### 2.4 初始化流程
分四步：(a) 图捕获（约 4 分钟）；(b) SM 限制 profiling（约 3 分钟）；(c) 每模型机器人上限基准测试（约 1 小时）；(d) 求解器执行机器人到 GPU 的分配（约 10 秒）。其中 (b)(c) 仅在模型集/max_batch/硬件变化时重跑，(d) 在机器人群体变化时重跑。
